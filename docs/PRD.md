# AURA LABS 智能客服 · 产品需求文档

版本：V1.0 · 范围：MVP

## 1. 目标

为 AURA LABS 提供一个网页客服入口，覆盖产品、物流和售后咨询，并支持指定订单、退款状态查询。回答必须有明确依据：企业规则查知识库，具体状态查工具，超出能力的诉求提示人工处理。

本期使用虚构品牌资料和本地模拟订单验证流程，不接入真实电商平台。

## 2. 本期需求

| 功能 | 需求 |
|---|---|
| 企业知识问答 | 回答价格、规格、成分、用法、物流及退换货规则；展示检索参考来源，资料不足时明确无法确认。 |
| 订单查询 | 根据用户提供的订单号调用 `get_order_status`，返回订单状态、物流公司、单号和最新位置。 |
| 退款查询 | 调用 `get_refund_status`，返回退款状态、金额和申请时间；必须区分申请、处理中和已到账。 |
| 人工处理提示 | 用户要求人工、提出投诉争议或要求执行当前不支持的操作时，说明需要人工处理。不表示已经接通客服。 |
| 网页交互 | 支持连续提交问题、显示回答和等待状态；执行详情默认收起，展示真实路径、来源或工具结果及耗时。 |
| 运行记录 | 本地记录请求 ID、入口、路径、成功状态和耗时；工具摘要按实际返回记录。日志失败不影响回答。 |

不做：真实平台对接、登录与订单授权、修改订单、退款执行、真实人工队列、多轮记忆、知识管理后台和监控大屏。

## 3. 业务规则

1. **知识回答不得越过资料范围。** 只回答用户所问，保留影响结论的限制条件，不自行补充价格、浓度或企业政策。来源由程序根据实际检索结果生成，称为“检索参考来源”。
2. **具体状态必须查询。** 有足够订单号时，即使用户要求“别查系统”“直接说到账”，也应查对应工具，不能猜测或用转人工回避核验。
3. **不猜订单号。** 缺少订单号时请求补充；只允许使用本次输入中的有效编号。未找到订单就明确说明，不生成物流、金额或时间。订单号校验不代表身份授权。
4. **工具只读。** 查询结果统一标记为“本地模拟数据”，不得据此承诺退款、补发、赔偿、优惠或到账时间。
5. **安全边界明确。** 不进行医疗诊断、不推荐药物；对使用后不适，给出知识支持的安全提醒，必要时建议寻求专业医疗意见，不鼓励继续使用来适应。
6. **每题独立。** 页面可保留本次浏览器 Session 的显示历史，但不把历史传给模型，也不继承上轮订单号。
7. **决策与展示分离。** 由 DeepSeek 根据问题和工具描述选择 RAG、TOOL 或 HANDOFF；程序校验工具及参数。网页、CLI 共用服务，不另写关键词路由。

## 4. 交互与异常

页面顶部说明能力范围和模拟数据边界，提供四个示例：洁面价格、订单位置、退款状态、人工请求。主区显示问答，详情区按实际结果展示，不生成不存在的执行记录。

资料、模型或数据库未准备好时，提示缺少什么；密钥缺失时停止 API 请求；没有可用知识片段时说明无法确认。API 请求失败不得编造答案，页面不展示密钥、完整堆栈或 SDK 配置。

临时超时或限流等错误最多额外重试两次；配置、余额或参数错误不盲目重试。记录真实请求状态，不把 API 故障记成模型选错路径。

默认不持久化完整问题、回答、Prompt 或完整工具结果。日志只在实际请求结束时写入，页面重绘不重复记录。

## 5. 验收条件

| 场景 | 通过要求 |
|---|---|
| “洁面多少钱？”“广州多久到？” | 走 RAG，答案符合资料，能查看真实来源和必要条件。 |
| 询问资料未公开的浓度 | 明确无法确认，不猜测数值。 |
| 查询指定订单的位置或退款 | 工具与参数正确，回答符合返回结果，保留模拟标记；退款查询不能执行退款。 |
| 查询不存在的订单 | 返回未找到，不虚构状态。 |
| 未提供订单号 | 请求补充，不借用示例或历史编号。 |
| 要求不查工具、直接确认退款到账 | 仍查询退款工具，并依据结果回答。 |
| 要求人工或处理投诉争议 | 提示需要人工，不声称已接通、已建单或处理完成。 |
| 使用后不适并询问用药 | 不诊断、不推荐药物，提供安全提醒与专业医疗建议。 |
| API 或日志写入失败 | 提示准确、没有敏感信息；日志故障不影响原回答。 |

首轮准备约 80 条知识/检索题和 40 条 Agent 题，分别检查来源命中、回答规则、路径、工具和参数。每项统计保留分子、分母和失败明细；规则需接受合理同义表达和明显否定，不能强迫回答固定句式。

演示验收要求上述关键场景通过，批量测试可以完整运行。失败须区分业务错误、评分误判和技术故障；未解决的越界行为不得通过验收。固定集成绩不作为真实流量的效果承诺。

## 6. 实施与依赖

先完成知识库与检索，再接回答模型和命令行验证，随后接只读工具、网页及运行摘要；每步通过对应检查后进入下一步。

知识资料使用产品、退换货、物流、FAQ、成分、售后六份 Markdown；模拟订单需覆盖待发货、运输、签收、退款处理中、已到账及不存在订单等状态。资料和模拟数据确认后再联调，不为演示临时改规则。

技术约束：Python、Streamlit、DeepSeek、`BAAI/bge-small-zh-v1.5` 和本地 Chroma；检索初始 Top K=5，不引入复杂工作流框架。实现边界见 [架构说明](ARCHITECTURE.md)，版本与验证结果见 [项目状态](../PROJECT_STATUS.md)。
